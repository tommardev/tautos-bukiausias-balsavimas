For humans · Step 1 of 2

Prepare the harness

Put the agent runtime in place before writing project conventions. First-time: the agent writes the files and restores skills. Joining a prepared clone: the files are already in git; the agent only restores skills on this machine. You install missing Cursor marketplace plugins once (/add-plugin — there is no CLI).

First time on a host? Open this kit on GitHub, paste the README prompt into an agent on the local project. The agent fetches kit/ and restores skills from GitHub. Joining a repo that already has AGENTS.md, skills-lock.json, and AI_CODING_README.md? Same prompt — restore this machine only; do not rewrite those files. Or follow AI_CODING_README.md on the clone.

Joining a prepared project

Skills installs are gitignored (.agents/skills/). Cursor marketplace plugins and API keys live on the developer’s machine. Committed files are the team’s workflow — leave them.

  1. From the repo root: npx skills experimental_install --yes
  2. Paste /add-plugin … only for plugins missing on this machine, then reload.
  3. Connect Context7 and Sonatype keys in Customize. Never commit keys.
  4. Read AI_CODING_README.md and AI_CODING_LEARN.md.

Do not fetch kit/ for join. Do not recopy harness defaults over existing .cursor/, skills-lock.json, or AI_CODING_* files.

Skills install (agent runs this)

The lockfile harness-defaults/skills-lock.json lists GitHub skill sources. After it is copied to the host git root, the agent must restore them (network). You should not clone skill repos yourself. Fallback if the agent failed:

Host git root

npx skills experimental_install --yes

Installs land in .agents/skills/ (gitignored). The lockfile stays tracked. Other clients (Cursor CLI, Claude Code, Codex, …) can use the same canonical folder.

Plugins (you, only if missing)

Writing settings.json does not download marketplace plugins, and there is no shell command that does. If the agent says a plugin is not already on this machine, paste that line in Cursor chat on the host:

Cursor chat

/add-plugin cursor-team-kit
/add-plugin context7-plugin
/add-plugin sonatype-cursor-plugin
/add-plugin modern-web-guidance

Then reload the window. Context7 and Sonatype need a key in Customize ("key": true in settings). Never commit the key. Skip any plugin the agent reports as already installed.

Default plugin block the agent merges into .cursor/settings.json: 

{
  "plugins": {
    "cursor-team-kit": { "enabled": true },
    "context7-plugin": { "enabled": true, "key": true },
    "sonatype-cursor-plugin": { "enabled": true, "key": true },
    "modern-web-guidance": { "enabled": true }
  }
}

Native rules (always-on)

Cursor loads .cursor/rules/*.mdc with alwaysApply: true on every chat — project-level pre-prompt. The kit copies harness-defaults/ai-coding-native-rules.md into ai-coding-native-rules.mdc only. Step 2 does not add globbed project .mdc files; when-to-load lives in AGENTS.md Pointers so non-Cursor harnesses see it. Optional: paste the same body into Customize → Rules → User Rules if you want the house workflow on every repo on this machine.

If a tool cannot load that rule file, step 2 still writes a short Tools stanza in AGENTS.md: Context7 MCP for library docs (not client search), Sonatype for versions and security, gh for GitHub.

IDE and CLI defaults

  • IDE: project .cursor/settings.json (plugins above).
  • CLI: project .cursor/cli.json — permissions only. Do not overwrite global ~/.cursor/cli-config.json unless you asked.
